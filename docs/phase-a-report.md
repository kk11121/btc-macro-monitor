## 実装した内容

- Claude と SEC の撤廃：Claude は FOMC 議事録の要約だけに残し（`claude-sonnet-5-5`、失敗時は「⚪ 判定不可」）、SEC の監視は撤廃した
- 不具合6件：すべて対応した。一覧になかった「〇月分と発表時刻の分離」も含む（例：`CPI（9月分）` と `発表 10/14 21:30（日本時間）`）
- ETF：SoSoValue を主に使い、キー未設定や失敗のときは TFTC で代替する。過去分の取り込みは TFTC から1回だけで、以降は `history/etf_flows.json` に貯めて90取引日で計算する
- ジョブ：朝のまとめと毎時の監視の2つにした。手動実行もでき、`--dry-run` も追加した
- 追加の指示：M2 と FRB バランスシートの必ず保存、Discord 失敗の指標ごとの切り離し、`state.json` が壊れたときの停止と通知を入れた

## 実データでの確認

- 通知を送らず、保存もしない dry-run で両ジョブが動いた
- 日付を古くした `state.json` のコピーで、経済指標と FOMC を含む全9種類の通知本文を確認した。CPI の4つの数値と NFP の実績は SoSoValue と一致した
- 実際の FOMC 声明から「据え置き、3.75〜4.00%」を正しく読み取れた

## 確認できていないこと

- Discord への実送信と、GitHub Actions 上の実行。ワークフローは YAML の構文だけ確認した
- 議事録の要約の成功経路。ローカルにキーがないので、確認したのは認証エラーで「⚪ 判定不可」になる経路だけ。次の議事録が本番での最初の確認になる
- Claude の拒否時の代替。サーバー側のフォールバックは入れていない。指示の「失敗時は判定不可」に合わせた

## レビューで直した主な問題

CRITICAL と HIGH はなく、次のような問題を直した。

- 未来の日付を保存すると ETF 通知が永久に止まる
- FOMC のページが一時的に取れないと「判定不可」で確定してしまう
- push に3回失敗しても成功扱いになる
- `@everyone` のメンションが有効になり得る

ほかにレビュー外で2点見つけて直した。

- 議事録が文字化けしていた
- 議事録の本文が8,000字で切られ、参加者の議論まで届いていなかった

## 既存のコードで見つけた問題

FRED の例外文には API キー入りの URL が含まれ、それがログに出る作りだった。今回の修正で出なくなった。過去のログについては、GitHub の Secrets マスクで隠れていたはずだが、確認はしていない。心配ならキーの再発行をすすめる。

## 見送った点

- 壊れた `state.json` の通知：直るまで毎時届く。回数の記録先そのものが読めないため
- Action の SHA 固定と push 用の認証情報の分離：今回の範囲外とした
- 長い通知の分割送信の途中失敗：再送すると前半が重複するが、朝のまとめは今のところ上限に届かない

## 配備後の動き

- 最初の実行で `state.json` が新形式に移行され、ETF の最新分が1回届く
- コア PCE と議事録は、初回は記録だけで通知しない

## お願いしたいこと

1. GitHub の Secrets に `SOSOVALUE_API_KEY` を登録する。未登録の間は TFTC で動く
2. コミットとプッシュに進んでよいか決める。プッシュすると本番の定時実行がすぐ新しいコードに切り替わり、通知も届き始める
3. 未追跡の `docs/`（設計書、事前確認、実装前の確認一覧）も一緒にコミットするか決める。README からリンクしているので、含めることをすすめる

`docs/redesign.md` の ForexFactory の URL と「空ならエラー」の方針は未修正なので、Phase B の前に直す必要がある。
