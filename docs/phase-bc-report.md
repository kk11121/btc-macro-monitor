## 実装した内容

### Phase B

- 発表日程：FRED の公式の予定日を `state.json` の `calendar` に控え、朝のまとめと（古ければ）毎時の監視で取り直す。時刻は `config.py` に固定（8:30、FOMC は 14:00、議事録は会合の3週間後）
- 予想値：SoSoValue（`/macro/events/{event}/history`）と ForexFactory の両方から取る。指標名は `config.py` の `FORECAST_METRICS` に固定で持ち、予定一覧（`/macro/events`）は使わない
  - 単位をそろえる：`"0.3%"`、`"0%"`、`"-0.4%"`、千単位の `"63"`・`"197"`、`"65K"`・`"194K"`
  - SoSoValue の履歴が0件なら指標名の誤りとしてエラー。次回の行がないだけならエラーにせず、ForexFactory だけで判定する
  - 取るのは朝のまとめと発表の3分前だけ。ForexFactory は1日2〜3回まで。発表直前に取れなかった出所は、朝に取れた値で補う
- 判定：2つの予想を範囲として比べる（それぞれの「同じとみなす幅」を含む）。片方ならその1つ、両方なければ前回値との比較で「予想値なし」
  - CPI はコア前月比で判定し、4つの数字を並べる。コア前年比が逆なら「前年比は逆方向」と添える。前年比の基準月が欠測なら「—（基準月のデータなし）」
  - 雇用統計は NFP で判定し、失業率を同じ通知に並べる（Phase A では別の通知だった）。逆なら「失業率は逆方向」と添える
  - 前年比は季節調整なし、前月比は季節調整ありの系列で計算し、小数1桁に丸めて比べる
- FOMC の利下げ確率：
  - 朝のまとめ：利下げ確率と前日比、3会合先までの織り込み幅と前日比を出す。利上げ確率が0でなければ並べる
  - 即時通知：利下げ確率か利上げ確率が、前回通知から15ポイント以上動いたら通知する（回答1）。強気・弱気は期待金利の向きで決める
  - 声明の判定：決定後の誘導目標の中央と、会合前の期待金利の差（±10bp）で判定する
- 朝のまとめの追加：「今日・明日の予定」（日本時間。予想値がなければ「予想 未発表」）、「金利見通し」、稼働状況の「SoSoValue 今月の残り○回」。上限の2割を切ったら警告する
- 発表待ち受け：毎時の監視に組み込み、その後60分以内に発表があれば待つ。発表時刻から30秒間隔で、最長45分取りに行く
  - CPI・雇用統計は BLS を見る（キーがあるとき）。新規失業保険申請・コアPCE は SoSoValue の実績を見る。新しい値がなければ FRED も見る
  - 発表時刻から実績が取れるまでの秒数を `logs/release_latency.jsonl` に書く
  - 45分で取れなければエラー通知（1回目と復旧時のみ）にし、次の回の予備確認（FRED）が拾う
- 二重通知の防止：経済指標の state に通知した発表日（`release`）を持つ
  - 予備確認は、待ち受けの対象になった発表を同じ回では見ない
  - 次の回では、FRED に新しい期間が出ていても、その発表日の分を通知済みなら記録だけにする

### Phase C

- 通知の記録：送れた通知をすべて `logs/alerts.jsonl` に1行ずつ書く（即時通知、日次フロー、朝のまとめ、月次、エラー、復旧）
  - 価格：通知時点と1・24・72時間後の BTC 価格は、毎時の監視の最後に書き足す。値はその時刻を含む OKX の1時間足の終値（確定した足だけ）
  - 取れなかった欄は空のまま残し、次の実行で再試行する
- 月次レポート：1日（日本時間）の朝のまとめのあとに前月分を送る（回答4）。中身は次のとおり
  - 送り先：Discord に要約、全文は `reports/YYYY-MM.md`
  - 集計：指標ごとの件数、当たり率（24・72時間後。中立と価格なしは除く）、全時間帯と比べた値動き幅の倍率、見直し候補
  - 送り直し：同じ月は2回送らない。手動の `--mode monthly --force` で送り直せる
- 過去分の復元：`scripts/reconstruct_history.py`。state.json の git 履歴から通知を復元し、その後の BTC の値動きを集計する。結果は `reports/` に保存した（下記）
- ワークフロー：
  - `logs/` と `reports/` もコミットする
  - `mode` に `monthly` を足した
  - `BLS_API_KEY` を渡す
  - 時間制限は毎時の監視が120分、ほかは20分
  - concurrency は1グループのまま（回答の変更点）

## cron-job.org の予定

**予定は増やさない。** 今の2つ（朝のまとめ 7:47、毎時の監視 毎時23分、どちらも Asia/Tokyo）のまま。送る内容も変わらない。

- 朝のまとめ：`{"ref": "main", "inputs": {"mode": "morning"}}`
- 毎時の監視：`{"ref": "main", "inputs": {"mode": "hourly"}}`

毎時23分の回が、その後60分以内の発表を待つ。米東部と日本の時差はちょうど1時間単位なので、米東部でも毎時23分になる。夏時間・冬時間のどちらでも、どの発表にも直前の回がある。

| 発表（米東部） | 待ち受けを始める回（米東部） | 冬時間の日本時間 | 夏時間の日本時間 |
|---|---|---|---|
| 8:30（CPI・雇用統計・新規失業保険申請・コアPCE） | 8:23 | 22:23 | 21:23 |
| 10:00（今は対象指標なし） | 9:23 | 23:23 | 22:23 |
| 14:00（FOMC声明・議事録） | 13:23 | 翌 3:23 | 翌 2:23 |

テストで確かめたこと：

- 冬（2026年12月10日）と夏（2027年6月10日）の両方で、3つの時刻の発表を直前の23分の回が拾い、その1つ前の回は拾わない
- 待ち受けを含む回が動きうる最長の時間帯（起動〜発表＋45分＋余裕10分）は、日本時間 20:23〜翌4:55 に収まる。朝のまとめ（7:47 から最長20分）とは重ならない

## 設計からの変更と、決めたこと

- FOMC声明が出たあと（米東部 14:00 以降）は、その日の会合を「次回会合」から外す
  - 理由：決定後は確率が 0% か 100% に寄り、声明の通知の直後に金利見通しの通知が重なるため
  - 動き：基準は次の会合に移るだけで、通知はしない
- 会合前の期待金利は、会合当日（日本時間）の朝のまとめで控える。当日の毎時の監視（米東部 14:00 前）と待ち受けの直前に、より直前の値で上書きする
- 月次レポートは、cron-job.org の予定を増やさないよう、1日の朝のまとめの中で送る（回答4。設計書の「毎月1日 0:17」から変更）
- 計画では Funding Rate の取得を `fetchers/okx.py` へ移すとしたが、変更を小さくするため `fetchers/glassnode.py` に残した。`okx.py` は検証用の1時間足だけを持つ
- 確率の表示は、設計書の見本に合わせて整数に丸めた（84.5% は「84%」）。通知の判定は丸める前の値で行う
- Phase A の state.json に残っていた `errors` の `nfp`・`unrate` は、移行のときに消す（雇用統計を `employment` にまとめたため）
